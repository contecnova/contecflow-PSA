==================================================
1) RESUMEN EJECUTIVO
==================================================
Se define una solucion final de colaboracion interna tipo Microsoft Teams para back office, con:
- Chat directo 1:1
- Chats grupales ad-hoc
- Equipos y canales
- Llamadas de voz y videollamadas
- Comparticion de archivos
- Busqueda avanzada
- Notificaciones y presencia
- Integraciones empresariales
- Seguridad, auditoria, retencion y legal hold

No es un MVP. Es alcance final completo para ejecucion por equipos de desarrollo y operacion.

3) ARQUITECTURA FINAL (CERRADA)
==================================================
3.1 Componentes principales
- Frontend Web (React/Vite existente)
- Backend API (FastAPI, dominio collaboration)
- WebSocket Gateway (eventos realtime)
- PostgreSQL (datos transaccionales)
- Redis (presencia, pub/sub, cache)
- NATS JetStream (eventos asincronos)
- OpenSearch (busqueda e indexacion)
- MinIO S3-compatible (archivos)
- ClamAV (antivirus)
- DLP Service (reglas de contenido)
- LiveKit SFU (voz/video)
- coturn (TURN/STUN)
- Observabilidad (OTEL, Prometheus, Grafana, Sentry)

3.2 Principios de arquitectura
- Multi-tenant por organization_id en toda capa de datos y servicios
- Seguridad by-default
- Event-driven para procesos asincronos
- Escalado horizontal para realtime y media
- Zero trust interno entre servicios

3.3 Flujo base de mensaje
1. Cliente autentica via SSO y obtiene token
2. Cliente abre websocket autenticado
3. Usuario envia mensaje a conversacion (1:1, grupo o canal)
4. Backend valida permisos y persiste en PostgreSQL
5. Evento se publica en Redis/NATS
6. Gateway distribuye a miembros conectados
7. Worker indexa contenido en OpenSearch
8. Sistema emite notificaciones segun reglas

3.4 Flujo base de archivo
1. Cliente solicita URL firmada de subida
2. Cliente sube a MinIO
3. Pipeline ejecuta antivirus y DLP
4. Si valido, backend publica metadata y notifica
5. Si invalido, archivo a cuarentena y alerta de moderacion

3.5 Flujo base de llamada
1. Usuario crea sala desde conversacion
2. Backend emite credenciales temporales LiveKit
3. Clientes se unen via WebRTC
4. coturn resuelve redes corporativas complejas
5. Opcional: grabacion/transcripcion con politicas activas

5) SLOS Y REQUISITOS NO FUNCIONALES
==================================================
- Disponibilidad anual: 99.95%
- Latencia p95 envio mensaje: < 350 ms
- Exito conexion llamadas: >= 98.5%
- RPO: 15 min
- RTO: 60 min
- Tamaño maximo archivo: 500 MB (configurable)
- Participantes por reunion: hasta 200 (escalable)
- Retencion default: 24 meses (ajustable por politica)

5.1 Politica unificada de duracion de sesion (backoffice + portal)
- La configuracion de sesion por inactividad se define en una fuente unica de settings.
- Claves canonicas: idle_timeout_enabled, idle_timeout_minutes.
- Debe aplicar tanto a usuarios internos (backoffice) como a usuarios del portal cliente.
- El warning de expiracion se muestra 60s antes del cierre en ambos frontends.
- La cookie/token del portal debe usar una duracion alineada con la politica de sesion configurada.
- Criterio de coherencia: no pueden existir valores de timeout divergentes entre backoffice y portal.

A.2.1 Provisionar infraestructura externa
  - LiveKit autohosteado (servidor + coturn)
       Variables: LIVEKIT_API_KEY / LIVEKIT_API_SECRET / LIVEKIT_URL
       Sin esto: las llamadas son single-user con cam/mic locales
  - Redis HA
       Variable: REDIS_URL + COLLAB_BUS_BACKEND=redis
       Sin esto: el bus es in-process (no escala a multi-worker)
  - NATS JetStream (alternativa a Redis)
       Variable: NATS_URL + COLLAB_BUS_BACKEND=nats
  - OpenSearch
       Variables: OPENSEARCH_URL + COLLAB_SEARCH_BACKEND=opensearch
       Sin esto: busqueda con LIKE / Pg-FTS (suficiente hasta ~1M msgs)
  - MinIO o S3
       Variables: COLLAB_S3_BUCKET + AWS_ACCESS_KEY_ID +
                  AWS_SECRET_ACCESS_KEY + COLLAB_STORAGE_BACKEND=s3
       Sin esto: archivos en filesystem local (uploads/)
  - ClamAV (clamd)
       Variables: CLAMAV_ENABLED=1 + CLAMAV_HOST + CLAMAV_PORT
                  o CLAMAV_SOCKET=/var/run/clamav/clamd.sock
       Sin esto: AV usa firma EICAR como deteccion minima
  - PostgreSQL HA con replica (RPO 15min)
  - Kubernetes para orquestacion
  - Stack observabilidad: OTEL + Prometheus + Grafana + Sentry
  - VAPID keys para Web Push:
       Variables: VAPID_PUBLIC_KEY + VAPID_PRIVATE_KEY + VAPID_CONTACT
       Generar con: python -c "from py_vapid import Vapid; v=Vapid(); v.generate_keys(); print(v.public_key, v.private_key)"
       Sin esto: el push esta deshabilitado (notificaciones in-app y
                email digest siguen funcionando)
  - SMTP server para email digest:
       Variables: SMTP_HOST + SMTP_USER + SMTP_PASS + SMTP_FROM (ya en config)
